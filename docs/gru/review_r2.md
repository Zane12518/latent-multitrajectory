原函数对照是“归档实现”与“独立安装的可移植适配模块”的一致性检查，**不是另一种独立设计的求解算法**。原函数仅将构造时 CUDA 设备改为 CPU；没有改循环、随机抽样和读出。48 个小批对照不等于全部历史 CUDA 输出逐值一致，也不是完整 benchmark 新评分。原配对区间未重抽。

新增源码仅增加保存数值数组复算入口和错误拒绝测试，模型、训练目标、推理规则与原 14 项测试未改。48 个对照在设备信息收尾失败后按同范围重试了一次，两次的成功前向日志均保留；不能只保留最后一份通过日志。

## 来源与许可

- 项目新接口、配置和测试：依既有项目代码 MIT 决定；不增加项目个人署名。
- 历史模型／目标／指标提取：保留原源树 MIT 和必要版权。两个原 build 的 AST 与源文件一致，核心提取文件与 portable_v4 一致；不把提取实现称为官方 GRAM。
- 24 个权重：来源为项目自建 GRU 训练端点；原 checkpoint→推理张量的既有导出记录与每模型三条评价绑定可追踪。当前仅重新核验可访问的导出文件，完整原 checkpoint 不可访问。
- 4 个逐题文件：已保存数值和集合差计数，不是原始预测或训练数据；与已公开汇总逐值一致。
- 权重、统计、数据维持现有非代码许可。内容安全检查和第三方 MIT 保留**不替代权属或本轮发布范围确认**；新文件继续私有。
- SATLIB 原始数据不打包。官方 UF20-91 获取／转换说明保留；3072训练和128 selection 为项目生成，不称官方划分。

## 失败、阻塞与 CI

1. 镜像继承的额外包源出现 DNS 重试；官方 PyTorch CPU 包下载和干净安装最终完成。之后的构建仅为本子进程使用显式公开源，没有修改平台全局配置。
2. 当前 CPU 容器的 `nvidia-smi` 为不可执行占位文件，首次审查在设备信息阶段报 `Exec format error`。失败日志保留，检测现改为明确记录不可用；模型／目标未因此变更。
3. 当前入口不可访问24个原完整 checkpoint；实时可见的5个 RUNNING 交互实例均为CPU。没有借用其他训练作业、启动GPU或执行CUDA续训。既有连续两步与中间保存恢复计划仍为 **NOT_SUBMITTED / NOT_VERIFIED**。
4. GitHub CI 未运行：本轮没有推送。候选 GRU 工作流已纳入两份测试文件；既有 `cpu.yml` 仍保留，会在将来正常推送／PR时触发其原验证范围，未将旧CI通过当成本次CI通过。待发布范围确认后再推送并核验新的真实CI。

所有校验值采用字节数／CRC32，另有张量和 AST 对照；不是来源认证。新旧日志和负结果均保留，测试知情开发、同起点续训流与固定模型区间的边界不变。
